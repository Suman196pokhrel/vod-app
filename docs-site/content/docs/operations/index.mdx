This section is the runbook for the production backend: deploying, setting up a server, managing secrets, debugging and recovering from incidents. It describes procedures and commands; it never contains secret values.

## At a glance

| | |
|---|---|
| Provider | Hetzner Cloud, one VPS |
| Memory | 3.72 GiB RAM + 2 GB swap (recorded in `infra/docker-compose.yml`) |
| Repository on the server | `~/vod-app` |
| Compose project | Run from `~/vod-app/infra` with `docker-compose.yml` and `prod.env` |
| Public hostname | `api.vod.spokhrel.dev` (Caddy, automatic HTTPS) |
| Frontend / docs | Vercel, deployed on push to `main` |

All commands in this section are run **on the server, from `~/vod-app/infra`**, unless stated otherwise. For brevity they use this alias:

```bash
alias dc='docker compose -f docker-compose.yml --env-file prod.env'
```

<Callout type="warn" title="Always pass the env file">
  Without `--env-file prod.env`, Compose fills in values for PostgreSQL, Redis, MinIO and tusd from
  `infra/.env` or built-in defaults, and may recreate those containers with the wrong configuration.
</Callout>

## Daily health check

```bash
dc ps                                            # every service Up
curl -s https://api.vod.spokhrel.dev/health/     # {"status":"Ok!"}
dc logs --since 24h worker | grep "\[queue\]"    # processing activity
df -h /                                          # disk headroom
```
